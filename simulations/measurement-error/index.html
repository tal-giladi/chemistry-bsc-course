How to use this, and why

Procedure
  1. Take a few readings of the same sample. Write each one down as it appears, with all digits shown.
  2. Compute the mean x̄ and the standard deviation s. Then uA = s/√n is the standard uncertainty of the mean.
  3. Add the Type B terms you know (resolution d/√12, a tolerance a/√3, a certificate U/k) in quadrature.
  4. Measure a reference standard the same way. The difference from its certified value is the bias of your method.
  5. Correct for the bias (or include it in the uncertainty), then report x̄ ± u with units and the number of readings.
Why each step is done
  • Repeats reveal random error and averaging reduces it: uA falls as 1/√n, so 4× more readings halve it.
  • Repeats cannot reveal a systematic error: a biased instrument is wrong the same way every time.
  • A reference standard (CRM) is the only way to see bias. Its own uncertainty limits how well you can know the bias.
  • Propagation shows which input dominates. Improve that one; improving the others is wasted effort.
Safety reasoning

Statistics has no hazards of its own, but a wrong uncertainty does: a drinking-water result reported as "below the limit" when its interval crosses the limit can hide a real problem. Report the uncertainty with every result, and never drop an inconvenient reading without a recorded reason (a blunder noted at the time, or a test such as Grubbs').

What can go wrong
  • Too few readings: with n = 3 the t-factor is 4.30, so the 95 % interval is very wide.
  • s = 0 when every reading shows the same digit: the scatter is hidden by the resolution. Use ures = d/√12.
  • Averaging away a bias: impossible. More readings make you more confident in the wrong number.
  • Treating a tolerance as a standard uncertainty: divide a ± limit by √3 first.
  • A small, poorly measured input (a 2 mL titre ± 0.3 mL): the first-order formula fails and the interval is asymmetric. Monte Carlo shows it.
